# v1.68.1 更新说明

## 修复

- **多设备共用号池时，小浣熊账号「同步过去就要求重新登录」根治**：小浣熊的刷新令牌是一次性轮换的——原机每刷一次，同步到其他机器的那份立刻作废。此前只有原机（与官方客户端共用同一份登录文件）能自动读到新值自愈，新机取不到新凭据，第一次刷新就被判「需重新登录」，于是「原机一切正常、新机一排号全红」。现在刷新被服务端拒绝时会先自动到其他设备把最新凭据取回来再试一次；如果对端的 access 令牌还没过期，还会直接复用（不再多刷一次把对端作废）。确属失效才提示重新登录，并说明是否已经尝试过跨设备取凭据
- **凭据新旧不再被「活动时钟」带偏**：多机同步原来拿账号的最后更新时间仲裁凭据，而它被额度刷新、冷却、备注、签到这些无关更新一路顶新——刚刷新失败的那台会凭已作废的凭据在同步里「胜出」，把另一台健康机器的凭据顶掉（反向污染）。现在单独记录凭据本身的写入时刻，只有凭据真的变了才推进；老版本对端的快照没有这个字段时仍按原口径比较，多版本混用不会互相踩
- **凭据是否过期改按 access 令牌的到期时间判**：小浣熊的额度接口不返回到期时间（库里恒为 0），此前「新鲜凭据」与「已过期凭据」根本分不出来，同步仲裁里「远端过期就坚决保住本机」那条规则形同虚设。现在本地解 JWT 到期时间参与判定（不发额外请求），过期凭据不会再覆盖可用凭据
- **号池同步拉取阶段的取消与网络错误不再被吞**：同步页点「取消」现在正确落「已取消」态（此前会显示失败并记一条错误日志），网络失败也恢复成可读文案而不是裸的 `fetch failed`

## 改进

- **刷新成功后立刻回传号池**：新增「只回传」同步模式（不拉取、不动删除墓碑、不碰共享配置）。小浣熊凭据一轮换就推一次，另一台最迟一个去抖窗口（60 秒）后拿到新凭据，不再干等到下一轮定时同步
- **疑似被顶号有了说法**：同一账号在别的电脑或客户端重新登录会产生新的会话标识（sid）。账号气泡里会留一条说明告诉你「疑似在别处重新登录过，同号多会话会被服务端互踢」，不必再猜是掉登录还是被顶号
- 失败原因分流：明确区分「服务端拒绝刷新（401）」「并发抢刷（200822）」「已尝试跨设备取凭据但没取到」等情况
