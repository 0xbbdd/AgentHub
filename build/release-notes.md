# v1.70.0 更新说明

## 新增

- **可以把中转站 / 自建端点接成一条渠道了**：「反代网关」新增「自定义提供商」页。填上游地址（填到 `/v1` 为止）+ 若干把 API Key 就是一个提供商，客户端仍只连网关那一个地址，模型名写 `标识/模型名`（如 `myrelay/gpt-4o`）即直达该端点。Key 直接进既有号池，轮转、冷却、熔断、租约、用量统计全部照常生效，不需要第二套实现
- **模型清单支持别名与元数据**：每个模型可配客户端名 / 上游真名 / 别名（别名能请求，但不进 `/v1/models`）、上下文与最大输出、倍率、能力位、思考档位；勾选若干模型后可批量设置（留空的字段不参与修改）
- **从上游拉取模型清单**：按三态 diff 展示（新增 / 已存在 / 上游已下架），新增默认不勾、上游已下架默认保留——删除必须是显式动作。带命名空间的上游模型名（`Qwen/Qwen2.5-72B` 这类）会自动拆成「客户端名 + 上游真名」，拉下来即可用
- **连通性探测**：整店「测试连接」与逐模型「测试」都发一次真实最小请求（会计费，界面已提示），但**不占号池租约、不写流水、不进冷却**——探测失败不会把一把好 Key 打成冷却；拿别名探测同样按清单里的真名映射走

## 修复

- **技能仓库「链接指向异常」以前根本裁决不了**：工具目录里那个位置有链接、但它不指向中央真身时，冲突列表列得出来、点「查看 / 裁决」却什么都不出现（只有行变亮），侧边栏红点不消、自动同步被这条硬冲突一直卡住。现在补齐了裁决面：先亮现场（链接指向哪份、目标还在不在、中央有没有对应真身），再给两个动词——「重建链接指向中央」（只换链接，它指向的内容一个字都不动）与「把链接那份收进中央」（复制而非移动，原目录保留，中央旧版先进回收站）；前提不满足的动词置灰并写明原因
- **同页两处「点了没反应」**：裁决结果提示会被紧随其后的重拉抹掉（成功与失败都看不到）；长列表时裁决面板落在屏幕外（列表本身内部滚动）。现在只有手动点「刷新」才清提示，点「查看 / 裁决」会把面板滚进视野
- **回收站同一毫秒归档两次会撞名**：一次裁决里「旧中央版进回收站」紧跟「原链接进回收站」正好踩中，POSIX 上会直接崩在最后一步。撞名时补 `-2/-3` 后缀
- **WorkBuddy 账号被上游风控拦截时，提示会把人带偏**：上游对部分账号在「模型调用」面上有风控（403 `request illegal` / code 11140），文案却写成「内容未通过安全审核，请调整后重试」——用户只会去改提问，改到天亮也不会好。现在识别为**账号级拦截**并如实说明（与提问内容无关，换号或在客户端重新登录该账号即可）：该账号落 2 小时冷却、请求内自动换号，且从号池切号到本地客户端之前会先探活一次，被拦的号不再写进客户端（未改动任何文件）

## 改进

- **提供商的模型绝不会顶掉内置渠道**：带前缀的写法直达提供商；裸名先问内置归属，内置拥有就不给提供商；只有一家提供商拥有时才允许裸名命中，两家都有直接报错不猜（配置里把 `proxy.allowBareProviderModel` 设为 `false` 可关掉裸名兜底，只留 `标识/模型名` 一种形态）
- **改了地址或模型清单不必重启网关**：适配器实例按「标识 + 更新时间」缓存，保存即生效
- **Key 管理**：移出前有确认（移出后密文即删，界面无从还原）；列表按「在线 / 总数」显示 Key 计数，启用中却一把 Key 都没有的行显式标「无 Key」——没有可用 Key 的提供商不会被调度
- **自定义请求头不能覆盖鉴权头**：`authorization` 一类由网关按号池的 Key 生成，保存时直接拒绝，避免绕开 Key 轮转与记账
