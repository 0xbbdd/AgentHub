# v1.70.1 更新说明

本次是对 v1.70.0 的一次复查整改：把最近 24 小时里新进来的代码逐条审了一遍，修掉两个会**直接掐断正常回答**的缺陷和几处「不报错但行为不对」的问题。每一条都补了回归断言（先证明它在修复前会红）。

## 修复

- **自定义提供商与 Cline 渠道的长回答会被 30 秒掐断**：网关的「首字节预算」计时器本该在第一个数据块到达时就解除，这两条路径漏了这一步，于是计时器在整条流期间一直武装，30 秒后直接掐断连接。表现是客户端拿到「HTTP 200 + 半截内容」，请求明细里也是一条看不出问题的成功记录（很容易被读成「上游只回了这一点」）。现在两条路径都在首个事件解除预算，且预算按提问规模放大（封顶 180 秒），超大提问不再被固定 30 秒误杀
- **自定义提供商的限流会被当成欠费**：中转站大量用「rate limit quota exceeded」这类措辞报限流，原来只要出现 quota 就判成余额耗尽，于是把该 Key 按「没钱了」冷却到次日 04:00——一个只是被限流的好号被静默跳过一整天，池子可用容量骤降。现在限流与欠费分开判：限流短退避换号，欠费才落冷却
- **账号的设备绑定信息可能被一次无关写入清空**：传入空对象本意是「这次不改」，实现却当成「整份替换」，会把机器指纹与备注一并清掉——跨机同步后表现为 Qoder 签名失败、小浣熊串号。现在空对象与不传同义
- **Claude Code / Codex CLI 直连网关时的两处转换问题**：内容块全被丢弃时（例如整条消息只有思考块或文档块）不再产出空消息——部分上游对空内容直接 400；Codex 的并行工具调用会合并进同一条助手消息，避免「工具结果找不到对应的调用」而报错
- **模型名提示在名字很短时会变成噪音**：写错模型名时网关会给「相近的模型」提示，但请求名去掉分隔符后不足 4 个字符时（例如只写了 `a`），任何含它的模型都会被列出来，三个名额被毫无关系的名字占满，比不提示更误导。现在短名只认「去掉分隔符后完全相同」，并按接近程度排序
- **自定义提供商里「模型名撞别名」会静默丢条目**：先给一个模型配了别名、又把该别名当成另一个模型的正式名字时，后者被静默丢弃（保存显示成功、模型却不生效）。现在这种情况直接报错说明
- **技能仓库裁决时收纳失败不再无声无息**：把链接指向的那份收进中央时若复制失败（磁盘满、权限），旧中央版已经在回收站里，原来只会抛一条看不懂的错误。现在明确告知可从回收站还原

## 改进

- **Key 列表批量删除的成功提示更可靠**：返回异常时不再误报「已删除 N 个」
- **`count_tokens` 端点与真实请求同口径**：缺 `max_tokens` 时也走同一条转换链，不再退回原始请求体估算

## 回归保障

新增两道自测闸，并给既有闸补了断言（全部做过变异验证——修复前必红）：

- `test-first-byte-budget`（24 项）：真 HTTP + 假上游复现「首块后延迟的第二块被掐断」，含「不解除预算必须真的断流」的正对照，以及全仓 8 个上游调用点的接线锚点
- `test-inbound-convert`（19 项）：Messages / Responses 两条入站转换的丢块边界与并行工具调用合并，含「带正文的消息不许被合并」等反向对照
