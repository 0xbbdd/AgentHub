# v1.79.1 更新说明

本版修 WorkBuddy 国际版免费模型的 429/6004 处理：不再把「账号×模型的频率上限」误读成额度耗尽，冷却按上游真实重置时间执行，避免反复重试和旧错误长期挂在号池卡片上。

## 反代网关 · WorkBuddy 国际版

- **6004 重置时间解析补全**：上游英文文案（`your usage will reset at ... UTC+8`）此前解析不到，冷却只能落 10 分钟兜底——真实重置还早时会每 10 分钟重试一次、看起来像额度永久用完；真实重置只剩几分钟时又比上游多关一段。现在正文里的日期时间（中英文都认）和 `Retry-After` 都会用于对齐真实重置时刻。
- **6004 不再写账号「最近错误」**：6004 只罚「账号×模型」，错误原因仍保留在模型级冷却的悬浮明细里；不再落到账号卡片，避免冷却/重置结束后仍挂着旧 429。号池卡片另外只把「上次成功调用之后」的错误标红，历史错误不再误导。
- **对话端点对齐官方客户端**：国际版优先走 `/v2/chat/completions`（本机 5.8.4 官方桌面客户端实际路径），`/console` 仅作 404/405 兜底；避免两条入口限频口径不一致带来的额外 6004。
- **流内 6004 正确归 429**：上游在 SSE 里返回 6004 时不再被当成 502 服务故障，客户端会按限频处理而不是立刻重试。
- **每日活跃保活让出 DeepSeek 免费窗口**：保活模型链改为优先 `hy3`/`hy4-preview`，`deepseek-v4.1-flash` 放最后，减少与真实对话抢同一个账号×模型额度。

## 说明

- 6004 是 WorkBuddy 对「账号×模型」的滚动频率上限，不是积分/余额耗尽；免费窗口打满时仍会按上游给的时间返回 429。需要在该窗口继续使用时，可在模型配置里把 `deepseek-v4.1-flash-sg`（付费孪生，约 0.03 credits/次）或其它免费模型配成 fallback。
- 旧版直接更新即可，数据无需迁移。

# v1.79.0 更新说明

本版给 WorkBuddy 国际版补上「每日活跃」保活三件事，修了 Trae 渠道的错误分类与目录过滤、Qoder 排队等待的无效重试，并把用量统计总览的加载从近 0.8 秒提到瞬时。

## 反代网关 · WorkBuddy 国际版

- **每日活跃保活（新功能）**：国际版上游没有「每日签到」体系，每日奖励的活跃判定挂在三条通道上，缺一条就领不到。本版在「签到」时把三件事一次做齐：① 活跃上报（点亮成长中心连登）；② 用免费模型发一次最小对话（保持账号有调用，不耗积分）；③ 网页通道建一个会话（每日活跃计数只认它）。
- 三件事都是尽力而为：任一步失败只显示失败原因，绝不影响加油包/签到的结论；仅国际版触发，国内版不发多余请求。
- 网页通道的请求剥掉桌面端指纹、只带必要凭据，会话体与浏览器端形态一致。

## 反代网关 · Trae 渠道

- **模型目录过滤三类非可选条目**：内部 subagent、租户自定义模型的占位模板、已下线开关不再混进模型目录；判据一律「缺省可见」，上游删字段时不会把整张表误滤空。
- **「模型不可用」错误改报 404**：上游 4001 表示该模型在当前通道不可用（不是服务故障），此前报 502 会让客户端以为上游挂了、反复重试同一个必死的模型；改 404 后客户端会直接换模型，账号不受罚。
- **「输入过大」独立成一档**：一次超长输入不再被当成账号错误——此前这类请求会顺着换号链把整池账号逐个罚掉，现在按 413 原样透传、零动作、不罚号。

## 反代网关 · Qoder 渠道

- **排队不再 1 秒白撞**：上游 10605 排队错误的正文里带着建议等待时长（实测 9~30 秒），此前不带时长只退 1 秒就重打，高峰期每个号都要白撞一遍。现在按上游建议落冷却并直接换号；上游没给时长时不猜值，行为与之前一致。

## 用量统计

- **总览加载提速约 1500 倍**：大库（13 万行）下总览一次加载从 778ms 降到 0.5ms——聚合查询加内存缓存（数据变化时自动失效、返回的是副本不串改），日期范围查询改走索引。改价/改别名/删设备/清缓存后结果立即重算，跨天自动刷新，不会看到旧数据。
- **AutoClaw 用量口径修正**：缓存读此前漏计，导致缓存命中率超 100%、计费净输入为负。现在新数据按全系统统一口径入库（input 含缓存读），历史存量自动补齐，总量与客户端计费一致。
- 托盘菜单同步精简：技能同步状态行已移除（入口保留在号池页）。

## 说明

- 本轮包含 5 个修复与 1 个新功能；旧版直接更新即可，数据无需迁移（历史 AutoClaw 存量在首次打开时自动修正）。

# v1.78.0 更新说明

本版给用量统计加了第 21 个数据源：**AutoClaw**（智谱 AutoGLM 桌面端）。本机装过并跑过任务，用量就会自动汇总进来。

## 用量统计

- **新增 AutoClaw 数据源**：直接读本机 AutoClaw 客户端的 `runtime.sqlite`（只读，不改动客户端数据），把主循环与协作子代理的 token 账归一到与其它数据源相同的口径。
- **账目口径与客户端自身计费一致**：主循环的 run 账、协作子代理每次 attempt 的账分别成条入库、聚合时相加，与客户端「run 总账 = 父 loop + Σ子 attempt」的计费投影一致，不会重复计。
- **国内版 / 国际版 / 旧目录都认**：自动识别 `AutoClaw-official`（国内）、`AutoClaw-oversea-official`（国际）与旧版 `AutoClaw` 目录；两区并存时可到「配置 · 用量统计 · 数据源」把另一区指过去（填根目录、账号目录或 runtime 目录都可以）。
- **长任务不漏账**：增量按「账目落定时间」而非「开始时间」判定——用量数据在 run 收尾时才写入，可能晚于上一次同步锚点，按落定时间判能正常收回，跨天的长任务也不会漏。
- 该源默认开启；没装 AutoClaw 的机器会自动跳过，不报错。

## 说明

- AutoClaw 既是本版的用量数据源，也是反代网关里已有的渠道，两者互不影响。
- README 的数据源清单已同步为 21 个。
